`/settings` is the workspace‑level configuration hub. This page is the
map of what lives where, what each tab does, and the licensing model
behind feature gates.

## The Settings tabs

Settings is grouped by product, and rows you have no license or no
permission for are not shown.

| Group                | Tab                     | Contents                                                                          |
| -------------------- | ----------------------- | ----------------------------------------------------------------------------------- |
| **Workspace**        | Workspace / Organization | Workspace name, timezone, and workspace-level identity.                           |
|                      | Access management       | A signpost to [Access management](/administration/access), not a second copy of it. |
|                      | Reviewers               | The reviewer roster used by triage workflows.                                       |
|                      | License                 | Current plan, enabled modules, seat count, expiry. Paste a new license key.          |
|                      | Billing                 | What you are on and how much of your allowance is left. Separate from License.       |
| **Runtime Security** | Custom rules            | Detection rules for the app firewall. See [Schedules & custom rules](/data-security/automation). |
| **DLP**              | Configurations          | A signpost to DLP → Configurations, where the fleet's policy actually lives.          |
| **Data Security**    | Scanning                | Default engine parameters and scan behaviour.                                        |
|                      | Healing and access      | Default healing toggles, auto-heal, retention, and dataset access control.           |
| **Platform**         | Integrations            | See [Integrations & webhooks](/data-security/integrations).                          |
|                      | Notifications           | Email, in-app, and webhook defaults per event type.                                  |
|                      | Appearance              | Theme, accent color, density, logo upload.                                           |

<Note>
  People, roles, resource access, API keys, authentication and SSO all
  moved to [Access management](/administration/access). Settings keeps
  a signpost row rather than a duplicate form, so there is one place a
  change can be made.

  The workspace two-factor rule moved with them: it now sits on
  **Access management → Directory**, beside the directory that enforces
  most of it.
</Note>

## Appearance

The Appearance tab controls how Blindsight looks for everyone in the
workspace.

- **Theme**: light, dark, or follow system. Per user, but the default
  is workspace‑wide.
- **Accent color**: a single workspace‑wide color used for buttons,
  links, and highlights.
- **Density**: compact for power users on large screens, comfortable
  for everyone else.
- **Logo upload**: appears in the top‑left nav, on report cover
  pages, and on shareable HTML report links.

<Tip>
  The logo you upload here also appears on the default report
  template's cover page. To override per project, set a
  project‑local report template (see [Compliance & reports](/compliance/reports)).
</Tip>

## Healing defaults

The Healing tab sets defaults for **every healing run in the
workspace**:

- **Default toggles**: which boxes are checked when the healing
  dialog opens.
- **Auto‑heal**: when set, every scan automatically queues a healing
  run with the default toggles. Useful for noisy pipelines.
- **Retention for cured zips**: how long the platform keeps healed
  downloads before garbage collection. Lineage stays even after the
  zip is purged.

## Security

| Setting           | Notes                                                                                       |
| ----------------- | ------------------------------------------------------------------------------------------- |
| Session timeout   | Idle timeout for browser sessions. Sub‑hour for highly regulated workspaces is common.       |
| Password policy   | Minimum length, complexity, expiry. Applies to invited users at password set time.           |
| 2FA               | Enable TOTP per user. When enforced workspace‑wide, users without 2FA cannot sign in.        |
| IP allowlist      | Restrict console / API access to a list of CIDR ranges.                                       |

## Licensing

Some features are gated behind license flags. The License tab shows
exactly what your workspace has access to.

| Feature flag                   | Gates                                                                    |
| ------------------------------ | -------------------------------------------------------------------------- |
| `FEATURE_DATA_SECURITY`        | Datasets, scans, and the rest of Data Security.                            |
| `FEATURE_RUNTIME_SECURITY`     | The firewall, its apps, keys, and endpoint DLP.                            |
| `FEATURE_RAG_SECURITY`         | [RAG Security](/data-security/rag-security) corpora and corpus scans.       |
| `FEATURE_COMPLIANCE_REPORTS`   | The whole [Compliance](/compliance/overview) product, including the audit trail. |
| `FEATURE_BIAS_ANALYSIS`        | The Bias & Shortcut engine.                                                |
| `FEATURE_DATA_DRIFT`           | Drift analysis.                                                            |
| `FEATURE_HEALING`              | Healing workflows.                                                         |
| `FEATURE_ADVANCED_EXPORTS`     | Export templates and the richer export formats.                            |

If a feature isn't licensed, the UI surfaces an **Upgrade required**
banner on the relevant page, and API calls return
`403 FEATURE_NOT_LICENSED` with the missing flag in the body.

### Updating your license

1. Your account manager sends you an updated license key (a short
   alphanumeric string).
2. **Settings → License → Paste new key**.
3. New modules light up within a minute.

The License tab also shows the current expiry date, the seat count,
and a usage summary so you can plan for renewals.

## Quotas

In addition to feature flags, your license has quotas:

- **Seats**: how many active users you can have.
- **Datasets and storage**: how much data you can keep at rest.
- **Concurrent scans**: how many scans can run at once.
- **Runtime Security calls**: per‑month quota for the firewall
  (counted across `/scan/input`, `/scan/output`, `/scan/tool-call`,
  and proxy calls).

When you cross a quota threshold, the UI surfaces a banner. When
you hit a hard limit, mutation APIs return an appropriate `402` or
`429`.

## Single‑tenant model

Blindsight Cloud is single‑tenant: each customer gets an isolated
deployment, managed by the Blindsight team, with its own database,
storage, and worker pool. Your workspace URL, severity counts,
licensing, and API keys are scoped to that one deployment.

This means:

- **Data isolation.** Your datasets, scans, and audit logs live only
  in your tenant.
- **Independent scaling.** Worker pools can be sized to your workload
  without affecting other customers.
- **Per‑tenant configuration.** Webhooks, custom rules, license
  modules, and quotas apply only to your workspace.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Live progress isn't updating">
    The scan UI uses a WebSocket (`/ws/api/scans/{id}`). If your
    network blocks WebSockets, progress still appears via polling
    every few seconds. No action needed.
  </Accordion>

  <Accordion title="Scan stuck in queued">
    No worker is consuming that engine's queue. Open a support
    ticket; this is on the Blindsight team to resolve on cloud.
  </Accordion>

  <Accordion title="HuggingFace import is slow or hits 429">
    HuggingFace rate‑limits aggressive imports. Blindsight retries with
    exponential backoff automatically. Check the retry counter on
    the import card; if it keeps failing, rotate to a fresh token
    under **Settings → Integrations**.
  </Accordion>

  <Accordion title="Compliance is missing from the sidebar entirely">
    Your license doesn't include `FEATURE_COMPLIANCE_REPORTS`. Gated
    products are hidden rather than shown as a dead entry, so the
    absence is the symptom. Contact your account manager or paste an
    updated key in **Settings → License**.
  </Accordion>

  <Accordion title="A tab I expected on Access management isn't there">
    Each tab asks the permission its own endpoints ask, so the strip
    never offers a surface the server would refuse. If Keys is missing
    you lack `settings.security.manage`; if Roles is missing you lack
    `roles.view`. See
    [Access management](/administration/access).
  </Accordion>

  <Accordion title="API call returns 402 QUOTA_EXCEEDED">
    You hit a per‑license quota. The response body includes a
    `usage` snapshot and an `upgrade_url`. Wait until the period
    resets or contact your account manager to top up.
  </Accordion>

  <Accordion title="Webhook deliveries stopped">
    Blindsight auto‑disables endpoints that consistently fail to
    protect the queue. Check **Settings → Integrations → Webhooks**
    for a disabled badge, fix the receiver, and re‑enable.
  </Accordion>
</AccordionGroup>
