The Blindsight API is the same REST interface the console uses. Use it
to automate Data Security, send prompts and responses through Runtime
Security, manage Apps and devices, pull compliance and audit records,
and administer a workspace.

## Base URL

Every workspace has a dedicated URL of the form:

```
https://<your-workspace>.blindsight.ai
```

The base URL appears in your welcome email and at the top of the
Settings page. Every example in this reference assumes you have set
`API_BASE` to this value. Self-hosted deployments use their own host.

```bash
curl -H "X-API-Key: $API_KEY" $API_BASE/api/datasets
```

## How the reference is organized

Endpoints are grouped by product area in the left navigation. Every
group has try-it-out enabled.

| Group                              | Use it to                                                                 |
| ---------------------------------- | ------------------------------------------------------------------------- |
| Identity and sign-in               | Log in, single sign-on, social sign-in, SCIM provisioning.                |
| Data Security                      | Projects, datasets, uploads and imports, scans, schedules, healing, RAG corpora, custom rules, the Playground. |
| Runtime Security (scan and proxy)  | Scan prompts, responses and tool calls, use the reverse-proxy routes, read events and health. |
| Runtime Security management        | Apps, devices and agents, discovery, DLP policy and installation.         |
| Compliance and audit               | Frameworks, the audit trail, reports and export templates.                |
| Workspace administration           | Workspaces, users, invitations, API keys, settings, directory sync, integrations, license. |
| Platform                           | Platform-level operations and inbound webhooks.                           |

The **Runtime Security (scan and proxy)** group is hand written, with
worked examples, and covers the calls an integration makes. The other
groups are generated from the running application. For guides, see the
[Runtime Security overview](/runtime-security/overview) and the
[Data Security overview](/data-security/overview).

## Conventions

- Requests and responses are JSON unless an endpoint says otherwise.
- Timestamps are UTC, ISO 8601, ending in `Z`.
- Paths begin with `/api`, except SCIM, which lives under `/scim/v2`.
