A workspace decides what its devices do with AI traffic by choosing
three protections. They are independent: any combination
works, so you can run Shadow AI alone, or protect personal data without
looking for injection.

Open **Endpoint → Configurations → Protections**. It is the first item
in the rail, and the only place the three are set.

## The three areas

The page is organised in levels. At the first level there is one choice
per area. Detail sits behind **Customize** under each area, so you only
open it when you need it.

| Area                           | Choices                          | What it does                                                                                                   |
| ------------------------------ | -------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **Personal data protection**   | **Off**, **Redact**, **Pseudonymize** | **Off**: prompts and uploads reach AI services unchanged. **Redact**: personal data is removed before it leaves the device. **Pseudonymize**: personal data is swapped for stand-ins before the prompt leaves the device and restored in the reply. |
| **Prompt injection detection** | **Off**, **Flag**, **Block**     | **Flag** records injection attempts and lets the prompt through. **Block** stops the prompt before it reaches the AI service. |
| **Shadow AI**                  | On or off                        | Devices record which AI services people use, including ones nobody approved.                                   |

A new workspace starts with all three on. Existing workspaces keep what
they had until you change it.

At least one area stays on. The last one that is on cannot be turned off;
to stop all of them, remove the agent. See
[Uninstalling the agent](/endpoint/uninstall).

Under the three areas, one line says whether AI services and policies
change any of these settings, for example how many of each. **Review**
opens a table of every policy and AI service that changes a setting, with
a link to edit it where it is set. If none do, the line reads that AI
services and policies follow these settings.

## Customize

### Personal data protection

Open **Customize** under **Personal data protection** to see:

- **Data types.** Each kind of value has its own choice: **Protect**,
  **Keep** or **Block**. See [What Protect, Keep and Block mean](#what-protect-keep-and-block-mean).
  Types are grouped: people and organisations, contact, identity
  documents by country (including the Mexican RFC, CURP and CLABE),
  financial, health and demographics, network, and secrets. Each group
  folds, and has **Protect all** and **Keep all**. **Search data types**
  finds one by name.
- **Sensitive data on device.** Runs a detection model on each device for
  the people, organisation and place types set to **Protect** or
  **Block**.
- With **Pseudonymize** chosen, two more settings appear:
  - **Keep stand-in keys for**: how many days a device can turn stand-ins
    back into real values. A chat resumed after this shows stand-ins.
  - **Same stand-in across chats for a day**: when on, every chat and
    upload on a device uses the same stand-in for a value for one day, so
    the model sees one person and not several. When off, each chat has its
    own stand-ins.

While **Customize** is closed, a quiet line says whether the data types
are at their defaults or how many you changed.

### Shadow AI

- **Unapproved AI** is **Record only**, **Protect** or **Block**. This is
  the posture towards services nobody has decided on. See
  [Shadow AI triage](/endpoint/shadow-ai/triage). **Protect** needs
  injection detection or personal data protection on, because it reads
  prompts.
- **Newly discovered AI** sets what happens the first time a service is
  seen. The default is the same as **Unapproved AI**.

A sentence under each area describes the choice you have made, so you
read the outcome and not only the control.

## What Protect, Keep and Block mean

| Choice      | What happens to the value                                                                                                  |
| ----------- | -------------------------------------------------------------------------------------------------------------------------- |
| **Protect** | The value is removed in **Redact** mode, or swapped for a stand-in in **Pseudonymize** mode.                               |
| **Keep**    | The value is left as typed. It is not a finding, so it is not recorded as personal data.                                   |
| **Block**   | The prompt is refused.                                                                                                      |

## Where each setting applies

Every row in the console shows where it runs next to its name. The data
types table has a **Device** column and a **Cloud scan** column.

| Setting                                  | Device                                              | Cloud scan                          |
| ---------------------------------------- | --------------------------------------------------- | ----------------------------------- |
| Prompt injection detection               | Decides whether the text is sent                    | Checks the text                     |
| Personal data protection on or off       | Yes                                                 | Yes                                 |
| Redact or Pseudonymize                   | Yes                                                 | No                                  |
| Data types                               | Yes                                                 | Yes                                 |
| Data types per AI service                | Yes, from desktop agent 2.1                         | Yes                                 |
| Sensitive data on device                 | Yes                                                 | No                                  |
| Stand-in settings                        | Yes                                                 | No                                  |
| Record retention                         | No                                                  | Kept by the platform                |

## At the foot of the page

- **What left devices** shows, for the last 7, 30 or 90 days, how much
  personal data was replaced on the device, how much the platform masked
  and how much reached the service as typed. It shows counts and
  categories only; no value is stored.
- **How long records are kept** sets how long prompt records, counts and
  the audit trail are kept.

## Pseudonymization

Pseudonymization used to have its own page. It is now part of
Protections: choose **Pseudonymize** under **Personal data protection**
and open **Customize**. The old address opens the personal data section.

### The pseudonymization suggestion

When personal data protection is on in **Redact** and a notable share of
the prompts inspected over the last seven days needed redacting, the
Endpoint pages show a small card suggesting **Pseudonymize**, with that
share. Pseudonymize replaces each value with a consistent stand-in, so the
AI service can still follow who and what a conversation is about.

- Only people who can change Protections see the card.
- It appears at most three times per person. Closing it with **X** hides
  it for good.
- It disappears once the workspace pseudonymizes, and it is not shown in
  workspaces that only share aggregated figures.
- The card only suggests. It changes no setting.

## What each combination does

| Combination                                   | What a device does                                                                                             |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| All three                                     | Reads prompts to approved services, protects personal data, flags injection, and records every AI service in use. |
| Injection and personal data, no Shadow AI     | Reads prompts, protects and flags, and does not record which services people use.                              |
| Shadow AI only                                | Records which AI services people use. **Prompts are never read.**                                              |
| Personal data only                            | Protects personal data in prompts and uploads. Nothing is checked for injection.                               |
| Injection only                                | Checks a redacted copy of each prompt for injection. Personal data is not changed.                             |

### Shadow AI only means no prompt is read

With injection and personal data both off, a device decrypts nothing. It
sees which AI services people connect to and nothing they send. The one
exception is a site you set to **Block**: the connection is ended only to
show the block page, and the request is never read or forwarded.

### Turning personal data off covers everything

With **Personal data protection** off, secrets and your custom rules stop
redacting too, not just personal data. The prompt reaches the AI service
unchanged. The copy sent to Blindsight for injection scoring is still
redacted on the device, so turning this off never sends raw personal data
to Blindsight.

## Confirm before turning one off

Saving a change that turns a protection off asks you to confirm, and
lists in plain words what will stop. The change is recorded in the audit
trail, one record per changed field. Turning a protection off is recorded
as high severity.

## What a person sees on their device

- **A blocked request.** A browser that is sent to a blocked AI service gets a
  block page with a reference.
- **Large uploads take longer.** Inspecting a large upload adds time. The upload
  completes.
- **Upgrades.** Plan agent upgrades outside working hours. See
  [Upgrades](/endpoint/install#what-an-upgrade-costs).
- **An uninstall that is refused.** When the workspace requires an uninstall code
  and none is given, the agent stays in place and keeps protecting. The refusal
  appears in the console within seconds as a tamper alert.
- **The tray app on a locked-down machine.** Where AppLocker rules block the
  agent's DLLs, the tray app does not start for a standard user. The service keeps
  protecting. The allow rules are on
  [Fleet rollout](/endpoint/fleet-rollout#locked-down-powershell-and-app-control).
- **What is on the computer.** A Windows service named `BlindsightDLP`, an
  inspection root certificate in the machine store, a small network adapter
  (Wintun) and the tray app. [Installing the agent](/endpoint/install#what-the-install-actually-changes)
  lists every change.

## Devices that do not honour a switch yet

A device on an older agent version follows what the platform tells it for
Shadow AI and for injection detection. An older agent keeps redacting
personal data whatever you choose, which is the safe direction. The page
shows how many devices are in that state, and they follow your choice
after they update.

## Licence

A protection your licence does not include shows **Not in your plan**
instead of a choice, and the platform refuses a request to turn it on.

## Who can change it

Changing protections needs `endpoint.protections.configure`. Admin and
`endpoint-admin` hold it by default. See
[Endpoint permissions](/endpoint/permissions).

## Setting it during Getting Started

The first question of **Connect people's devices** in Getting Started is
**What should devices do?**, with the same three switches. All three
start ticked. It saves as you go and shows the same page as above, so the
two cannot disagree. The rest of the steps follow your choice: with
Shadow AI off, the first-AI-service milestone is replaced by the first
protected prompt.

## The API

```bash
curl $API_BASE/api/runtime-security/dlp/protections \
  -H "Authorization: Bearer $TOKEN"
```

`GET` returns the three protections, their sub-choices, which are
licensed, and how many devices do not yet honour a switch. `PUT` takes
any of them and saves in one transaction. It refuses turning all three
off, refuses **Protect** when both prompt-reading protections are off,
and refuses turning on a protection your licence lacks.
