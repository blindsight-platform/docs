## What Blindsight does

Blindsight is a safety platform for AI systems, delivered as a managed
cloud service. Three surfaces inspect, one turns what they found into
evidence. Use whichever fit your stack.

<Columns cols={2}>
  <Card
    title="Data Security"
    icon="shield-check"
    href="/data-security/overview"
  >
    Scan training datasets and RAG corpora for label errors, outliers,
    poisoning, bias, leaked secrets, and prompt‑injection payloads. Triage,
    heal, and quarantine.
  </Card>
  <Card
    title="Runtime Security"
    icon="bolt-lightning"
    href="/runtime-security/overview"
  >
    A drop‑in firewall for LLM traffic. Scan prompts before they reach the model
    and responses before they reach the user.
  </Card>
  <Card title="DLP (endpoint)" icon="laptop" href="/dlp/overview">
    A signed desktop agent that intercepts LLM traffic at the OS network layer
    on every managed laptop. No application code changes.
  </Card>
  <Card title="Compliance" icon="scale-balanced" href="/compliance/overview">
    Map everything the other three surfaces observed onto SOC 2, ISO 27001,
    HIPAA, GDPR, the Swiss FADP, and the EU AI Act. Then generate the report.
  </Card>
</Columns>

The three inspection surfaces share the same scanners, the same Apps,
the same event store, and the same admin console. They ship
independently so you can adopt one (or two) without committing to the
rest, and Compliance reads whichever of them you run.

## How the surfaces relate

|                      | Data Security                                    | Runtime Security                                            | DLP (endpoint)                                                  |
| -------------------- | ------------------------------------------------- | ----------------------------------------------------------- | --------------------------------------------------------------- |
| **What it inspects** | Datasets at rest and RAG corpora (images, text, NIfTI, detection) | Live LLM prompts and responses from instrumented apps       | Live LLM prompts and responses from any app on a managed device |
| **When it runs**     | On upload, on schedule, on demand                 | On every request, inline                                    | On every request, on the device                                 |
| **Who deploys it**   | The data / ML team                                | The application team                                        | IT, via MDM                                                     |
| **Integration**      | Web UI, REST API, scheduled scans                 | Reverse proxy (swap `base_url`) or REST scan endpoints      | Push the signed agent through Jamf, Kandji, Intune, GPO, SCCM   |
| **Output**           | Issue lists, healed datasets, compliance reports  | `allow` / `redact` / `block` verdicts, events, drift charts | Same verdicts, attributed to a device and a directory user      |

If you only need one surface today, start there. Wiring up the rest
later is additive: workspaces, Apps, API keys, observability, and audit
already know about all three.

[Compliance](/compliance/overview) sits on top of whichever of them you
run. It adds no scanners of its own; it maps what they already found
onto SOC 2, ISO/IEC 27001, HIPAA, GDPR, the Swiss FADP, and the EU AI
Act, and produces the document an auditor asks for.
