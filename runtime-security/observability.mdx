The persisted event log powers a set of read-only endpoints plus a
streaming surface. Use them to answer "what is the firewall doing
right now" without rerunning anything.

## Authentication

Every endpoint on this page is a `GET` that you call with an
[API key](/administration/api-keys) in the `X-API-Key` header. The key needs
the **Read threat events** permission (`runtime:events:read`). A key with
**Full Runtime Access** (`runtime:*`) or full platform access also works. A key
acts as the person who created it, so it can only read what that person can
read.

Without a valid key the API returns `401`. With a key that lacks the
permission it returns `403`. If Runtime Security is not enabled for the
workspace, it returns `404`.

## Analytics

### `GET /api/runtime-security/analytics`

Aggregate counts for a time window.

| Parameter | Type             | Notes                                                                                   |
| --------- | ---------------- | --------------------------------------------------------------------------------------- |
| `days`    | int              | 1 to 3650. Default 14. The last N days.                                                 |
| `minutes` | int              | 1 to 5256000. A window of the last N minutes. Overrides `days`.                         |
| `start`   | datetime         | Start of an absolute window, ISO 8601 in UTC (for example `2026-11-01T00:00:00Z`). Send it together with `end`. |
| `end`     | datetime         | End of an absolute window. Must be after `start`. When `start` and `end` are set they override `days` and `minutes`. |
| `app`     | string, repeated | An App UUID. Repeat the parameter to include several Apps. An unknown App returns `400`.|

Sending only one of `start` and `end`, or an `end` that is not after `start`,
returns `400`.

The response has these fields:

| Field                    | Notes                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------- |
| `range_days`             | The `days` value of the request.                                                            |
| `range_minutes`          | The length of the window in minutes.                                                        |
| `bucket_seconds`         | The width of one `series` bucket: 60 for windows up to an hour, 3600 up to a day, otherwise 86400. |
| `totals`                 | Counts for the window: `total`, `input`, `output`, `tool_call`, `pii_hits` (events with personal data) and `injection_hits` (events with an injection finding). |
| `verdict_breakdown`      | Event counts for `allow`, `flag`, `redact` and `block`.                                     |
| `pii_category_breakdown` | Event counts per category of personal data.                                                 |
| `avg_latency_ms`, `p95_latency_ms` | Scan time. `null` unless the person who owns the key may view firewall latency. |
| `series`                 | One entry per bucket, oldest first: `date` (the bucket start in UTC, `YYYY-MM-DD` for daily buckets and `YYYY-MM-DDTHH:MM` for shorter ones), `allow`, `flag`, `redact`, `block` and `total`. |

```bash
curl -H "X-API-Key: $BLINDSIGHT_API_KEY" \
  "https://platform.blindsight.io/api/runtime-security/analytics?days=7"
```

```json
{
  "range_days": 7,
  "range_minutes": 10080,
  "bucket_seconds": 86400,
  "totals": {
    "total": 6200,
    "input": 4100,
    "output": 2050,
    "tool_call": 50,
    "pii_hits": 210,
    "injection_hits": 31
  },
  "verdict_breakdown": {"allow": 5950, "flag": 12, "redact": 210, "block": 28},
  "pii_category_breakdown": {"email": 120, "phone": 55, "person": 35},
  "avg_latency_ms": null,
  "p95_latency_ms": null,
  "series": [
    {"date": "2026-10-28", "allow": 850, "flag": 2, "redact": 30, "block": 4, "total": 886}
  ]
}
```

### How to read the numbers

| Field                       | What it tells you                                                                 |
| --------------------------- | --------------------------------------------------------------------------------- |
| `verdict_breakdown`         | The shape of your traffic. If `block` spikes, investigate before tuning. A rising `flag` count means more events are being recorded for review; see [Verdicts](/runtime-security/verdicts). |
| `pii_category_breakdown`    | Which categories of personal data are actually showing up. Drives custom rule decisions. |
| `series`                    | The time series. Plot it to see weekend and weekday rhythms or rollout impact.    |

## Event log

### `GET /api/runtime-security/events`

Paginated event list, newest first. Includes events from the desktop
app as well as from API and SDK calls.

| Parameter      | Type     | Notes                                                                 |
| -------------- | -------- | --------------------------------------------------------------------- |
| `limit`        | int      | 1 to 500. Default 50.                                                 |
| `offset`       | int      | Number of events to skip. Use it to page: `0`, then `limit`, and so on. |
| `date_from`    | date     | `YYYY-MM-DD`. Events from this day onwards (UTC, inclusive).          |
| `date_to`      | date     | `YYYY-MM-DD`. Events up to and including this day (UTC). Defaults to today. |
| `days`         | int      | The last N days, today included. Ignored when `date_from` is set.     |
| `verdict`      | string   | Filter to `allow`, `flag`, `redact`, or `block`.                      |
| `direction`    | string   | Filter to `input`, `output`, or `tool_call`.                          |
| `device_only`  | bool     | Only events from enrolled desktop app devices.                        |

The response has `total` (the number of events that match the filters),
`items` (the current page) and `identity_mode` (whether people and devices
are named or shown as codes). Each event has these fields and no others:

| Field             | Notes                                                                                   |
| ----------------- | --------------------------------------------------------------------------------------- |
| `uuid`            | Event identifier.                                                                       |
| `created_at`      | UTC, ISO 8601, ending in `Z`.                                                           |
| `verdict`         | `allow`, `flag`, `redact`, or `block`.                                                  |
| `direction`       | `input`, `output`, or `tool_call`.                                                      |
| `reason`          | `prompt_injection`, `harmful_content`, `pii`, `policy`, or `null` for a clean pass.     |
| `provider`        | The AI provider, or `null`.                                                             |
| `source_app`      | The service host, or `null`.                                                            |
| `model`           | The model, or `null`.                                                                   |
| `device_hostname` | The device, from the desktop app. A code when the workspace does not name devices.     |
| `device_os_user`  | The operating system user on the device. A code when people are not named.             |
| `process_name`    | The application on the device that sent the request, when known.                       |
| `user_email`      | The person the device is bound to. A code when the workspace does not name people.     |
| `pii_categories`  | The categories of personal data found.                                                  |
| `redacted_text`   | The stored text, according to the workspace's privacy settings.                         |
| `text_length`     | Length of the original text in characters.                                              |

A `verdict` of `flag` also includes events that were redacted or blocked and
that carried an injection, so a filter on `flag` finds every event with an
injection.

`GET /api/runtime-security/events/{uuid}/explain` returns the same fields for
one event.

Authenticate with an [API key](/administration/api-keys) that has the
**Read threat events** permission, sent in the `X-API-Key` header. A key
created for **Endpoint** with **Read endpoint events** works for desktop app
events.

```bash
curl -H "X-API-Key: $BLINDSIGHT_API_KEY" \
  "https://platform.blindsight.io/api/runtime-security/events?verdict=flag&device_only=true&date_from=2026-11-01&limit=500&offset=0"
```

To read everything in a window, keep the same filters and increase
`offset` by `limit` until a page returns fewer items than `limit`.

Automated background requests that AI web apps send while they run, such as
settings, identifiers and telemetry, are not recorded as prompts. The events
API does not return them and the console does not count them.

### Example response

```json
{
  "total": 137,
  "identity_mode": "named",
  "items": [
    {
      "uuid": "6b0f3c1e-2a4d-4f57-9a1e-0c5d8e7b4a12",
      "created_at": "2026-11-02T14:07:31Z",
      "verdict": "flag",
      "direction": "input",
      "reason": "prompt_injection",
      "provider": "openai",
      "source_app": "chatgpt.com",
      "model": "gpt-4o",
      "device_hostname": "LAPTOP-0042",
      "device_os_user": "jsmith",
      "process_name": "chrome.exe",
      "user_email": "jsmith@example.com",
      "pii_categories": [],
      "redacted_text": "Summarise this document for me",
      "text_length": 31
    }
  ]
}
```

### Page through events

`total` counts every event that matches your filters, so you can size the
job up front. Keep the filters fixed and move `offset` forward by `limit`:

```bash
LIMIT=200
OFFSET=0
while :; do
  PAGE=$(curl -s -H "X-API-Key: $BLINDSIGHT_API_KEY" \
    "https://platform.blindsight.io/api/runtime-security/events?date_from=2026-11-01&limit=$LIMIT&offset=$OFFSET")
  COUNT=$(echo "$PAGE" | jq '.items | length')
  echo "$PAGE" | jq -c '.items[]'
  [ "$COUNT" -lt "$LIMIT" ] && break
  OFFSET=$((OFFSET + LIMIT))
done
```

New events arrive at the top while you page, which shifts later pages. For a
one-off export, set `date_to` to a day that has ended so the window does not
move. For a feed you poll, de-duplicate on `uuid`.

### One event

```bash
curl -H "X-API-Key: $BLINDSIGHT_API_KEY" \
  "https://platform.blindsight.io/api/runtime-security/events/6b0f3c1e-2a4d-4f57-9a1e-0c5d8e7b4a12/explain"
```

The response is a single object with the fields in the table above, plus
`identity_mode`. An unknown `uuid` returns `404`.

## Drift

### `GET /api/runtime-security/drift`

Compares how your traffic looks in a recent window against a longer baseline
window, using the Population Stability Index (PSI) per dimension.

| Parameter       | Type             | Notes                                                                       |
| --------------- | ---------------- | --------------------------------------------------------------------------- |
| `baseline_days` | int              | 2 to 365. Default 30. The length of the baseline window, ending now.         |
| `recent_days`   | int              | 1 to 90. Default 7. The recent window, ending now. Must be smaller than `baseline_days`, otherwise `400`. |
| `app`           | string, repeated | An App UUID. Repeat the parameter to include several Apps. An unknown App returns `400`. |

The response has `baseline` and `recent` (each with `start`, `end` in UTC and
`total_events`), `daily_volume` (`date` and `count` per day), and
`dimensions`, sorted with the largest shift first. Each dimension has:

| Field                                      | Notes                                                              |
| ------------------------------------------ | ------------------------------------------------------------------ |
| `name`, `label`                            | The dimension, for example `verdict` ("Verdict mix").              |
| `psi`                                      | The PSI value for the dimension.                                   |
| `severity`                                 | `stable`, `moderate` or `high`.                                    |
| `baseline_distribution`, `recent_distribution` | The share of events per category in each window.               |
| `top_shifts`                               | The categories that moved most: `category`, `baseline_share`, `recent_share`, `delta`, `baseline_count`, `recent_count`. |
| `psi_series`                               | `date` and `psi` per day of the recent window.                     |

Dimensions you can read: `verdict`, `direction`, `source_app`, `model`,
`provider` and `pii_category`.

```bash
curl -H "X-API-Key: $BLINDSIGHT_API_KEY" \
  "https://platform.blindsight.io/api/runtime-security/drift?baseline_days=30&recent_days=7"
```

```json
{
  "baseline": {"start": "2026-10-04T09:00:00", "end": "2026-11-03T09:00:00", "total_events": 21400},
  "recent": {"start": "2026-10-27T09:00:00", "end": "2026-11-03T09:00:00", "total_events": 5100},
  "dimensions": [
    {
      "name": "verdict",
      "label": "Verdict mix",
      "psi": 0.03,
      "severity": "stable",
      "baseline_distribution": {"allow": 0.96, "redact": 0.03, "block": 0.01},
      "recent_distribution": {"allow": 0.95, "redact": 0.04, "block": 0.01},
      "top_shifts": [
        {"category": "redact", "baseline_share": 0.03, "recent_share": 0.04, "delta": 0.01, "baseline_count": 640, "recent_count": 204}
      ]
    }
  ],
  "daily_volume": [{"date": "2026-11-02", "count": 740}]
}
```

PSI ranges roughly:

| PSI value     | Reading                                                            |
| ------------- | ------------------------------------------------------------------ |
| `< 0.1`       | Stable. No action.                                                  |
| `0.1 – 0.25`  | Mild drift. Worth a glance.                                         |
| `> 0.25`      | Significant drift. Investigate.                                     |

A dimension with a high PSI is a prompt to open the event log for the same
window and see what changed.

## Health

### `GET /api/runtime-security/health`

Tells you whether the firewall is on and ready to scan. Use it as a readiness
check in your own tooling.

| Field     | Notes                                                                                           |
| --------- | ----------------------------------------------------------------------------------------------- |
| `enabled` | Whether the firewall is turned on for the workspace. When `false`, scan calls return `503`.     |
| `status`  | `ready`, `degraded` or `disabled`. `degraded` means the firewall is up but not fully ready, for example while it is starting. |

The response carries further fields for operators. Only `enabled` and `status`
are part of the supported contract.

```bash
curl -H "X-API-Key: $BLINDSIGHT_API_KEY" \
  "https://platform.blindsight.io/api/runtime-security/health"
```

```json
{"enabled": true, "status": "ready"}
```

## Service status

### `GET /api/runtime-security/service-status`

Whether the firewall service behind the scan endpoints is running.

| Field         | Notes                                                                          |
| ------------- | ------------------------------------------------------------------------------ |
| `provisioned` | Whether this deployment has a firewall service at all.                         |
| `ready`       | `true` when at least one firewall instance is running and can serve scans.     |

The response carries further fields that describe the hosting deployment. They
are not part of the supported contract. If the status cannot be read, the
endpoint returns `503`.

```bash
curl -H "X-API-Key: $BLINDSIGHT_API_KEY" \
  "https://platform.blindsight.io/api/runtime-security/service-status"
```

```json
{"provisioned": true, "ready": true}
```

## Streaming

Rolling‑window streaming with mid‑stream cancellation is **supported**
on the following proxy routes:

- OpenAI (`stream=true`)
- Anthropic (`stream=true`)
- Every OpenAI‑compatible provider (Groq, DeepSeek, Perplexity,
  Mistral, OpenRouter, Cerebras, self‑hosted)
- Google Gemini (`:streamGenerateContent`)
- Vertex AI (`:streamGenerateContent`)

Upstream chunks forward to your client immediately; the firewall
scans the assembled response on a rolling cadence and emits a
provider‑shaped terminal chunk on `block`.

### Not yet streamed

- AWS Bedrock `/converse-stream`, uses the AWS event‑stream binary
  framing that needs a custom parser. Use the non‑streaming
  `/converse` route for now.
- Legacy OpenAI `/v1/completions`, rejected with `400`.

If your use case is compliance‑strict (no mid‑stream leakage
allowed), use a non‑streaming route and buffer‑then‑stream from your
own code.

## Common workflows

<AccordionGroup>
  <Accordion title="Quarterly review">
    Pull `analytics?days=90` for each App. Plot verdict mix and PII
    categories alongside your model release timeline to see what
    changed.
  </Accordion>

  <Accordion title="Tune a noisy App">
    1. `drift?baseline_days=30&recent_days=3&app=<app-uuid>` to see what's shifted.
    2. Open the event log for the same App and window, filtered to the
       verdict or direction that moved.
    3. Adjust the App's configuration, then watch the next drift run.
  </Accordion>

  <Accordion title="Ship live data to your SIEM">
    Poll `/events` from a scheduled job with `date_from` set to the
    last day you collected, paging with `limit` and `offset`. Skip
    events whose `uuid` you already have, and push the rest to your
    SIEM with the `uuid` so cross‑system queries can join on it.
  </Accordion>
</AccordionGroup>
