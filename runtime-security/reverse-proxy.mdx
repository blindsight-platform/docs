---
title: "Reverse proxy"
description: "Wire-compatible passthrough endpoints for OpenAI, Anthropic, Gemini, Vertex, Bedrock, and self-hosted runtimes. Swap one config value to put Blindsight in front of LLM traffic."
---

The reverse proxy lets a client application put Runtime Security in front of
its LLM traffic by changing a single configuration value, the SDK `base_url`.
Every prompt is scanned before it reaches the upstream provider and every
response is scanned before it returns to the caller. Verdicts, redaction and
events work the same way as for the [Scan API](/runtime-security/scan-api).

**Supported providers:**

- **Native routes**: OpenAI, Anthropic (Claude), Google Gemini, Google
  Vertex AI, AWS Bedrock.
- **OpenAI-compatible**: Groq, DeepSeek, Perplexity, Mistral AI,
  OpenRouter, Cerebras.
- **Self-hosted via OpenAI-compatible**: Ollama, llama.cpp, vLLM,
  on-prem TGI, or anything else exposing an OpenAI-shaped API.

## Why a reverse proxy

The Scan API asks you to call the firewall at two points in your code. The
proxy is the better fit when:

- Your application already goes through an OpenAI or Anthropic SDK and you
  want no code changes beyond `base_url`.
- You use third-party tools (LangChain, LlamaIndex, `curl`, Cursor and so on)
  where the wire protocol is the only contract.
- You want a hard guarantee that every call went through the firewall,
  enforced at the network boundary.

## Endpoints

All routes are `POST` and live under `/api/runtime-security/proxy`.

| Path                                                                                      | Upstream                                                                            |
| ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `/openai/v1/chat/completions`                                                             | `https://api.openai.com/v1/chat/completions`                                        |
| `/openai/v1/completions`                                                                  | `https://api.openai.com/v1/completions`                                             |
| `/anthropic/v1/messages`                                                                  | `https://api.anthropic.com/v1/messages`                                             |
| `/openai-compatible/v1/chat/completions`                                                  | Chosen by `X-Blindsight-Upstream-Provider`, `X-Blindsight-Upstream-Base` or the App's routing |
| `/openai-compatible/v1/completions`                                                       | Same as above                                                                       |
| `/gemini/v1beta/models/{model}:generateContent`                                           | `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`   |
| `/gemini/v1beta/models/{model}:streamGenerateContent`                                     | The same host, streaming                                                            |
| `/vertex/v1/projects/{project}/locations/{location}/publishers/google/models/{model}:generateContent` | `https://{location}-aiplatform.googleapis.com/...`                      |
| `/vertex/v1/projects/{project}/locations/{location}/publishers/google/models/{model}:streamGenerateContent` | The same host, streaming                                          |
| `/bedrock/model/{modelId}/converse`                                                       | `https://bedrock-runtime.{region}.amazonaws.com/model/{modelId}/converse`           |

Gemini accepts only `:generateContent` and `:streamGenerateContent`. Any other
action returns `400` with the status `unsupported_endpoint`.

## Authentication

You send two credentials: one for Blindsight and one for the upstream provider.

An [API key](/administration/api-keys) with the **Scan prompts and responses**
permission (`runtime:scan`) authenticates you to Blindsight. A key with
**Full Runtime Access** (`runtime:*`) or full platform access also works.
Send it in one of two headers:

1. `X-API-Key: ak_...`. Use this with OpenAI, OpenAI-compatible, Gemini,
   Vertex and Bedrock clients.
2. `X-Blindsight-Key: ak_...`. Use this when the client already uses
   `x-api-key` for the provider, as the Anthropic SDK does.

`Authorization` is never read by the proxy. It is forwarded to the provider as
you send it, except that a value starting with `ak_` is dropped so a Blindsight
key never reaches an upstream.

| Status | When                                                                                     |
| ------ | ---------------------------------------------------------------------------------------- |
| `401`  | No Blindsight credential, or the key is invalid, expired or disabled.                    |
| `403`  | The key does not have the `runtime:scan` permission, or its owner no longer holds it.    |
| `404`  | Runtime Security is not enabled for the workspace.                                       |
| `503`  | The firewall is disabled for the workspace.                                              |

### App attribution

Add `X-Blindsight-App-Id` with the UUID of an App to attribute the traffic to
it. The App's configuration then applies to the request. If you omit the header,
a key limited to one App uses that App, and a workspace with exactly one App
uses it. A key limited to several Apps must send the header (`400`,
`APP_ID_REQUIRED`).

Other App errors: `400` `APP_NOT_FOUND` for an unknown App, `423`
`APP_DISABLED`, `410` `APP_ARCHIVED`, and `429` `APP_QUOTA_EXCEEDED` (with a
`Retry-After` header) when the App's own event limit is reached. If the App
requires signed requests, send `X-Blindsight-App-Token` as well.

### Usage

One exchange through the proxy, a prompt and its reply, uses two requests from
the workspace allowance. When the allowance is used up, the proxy answers with
a provider-shaped error and status `402` before anything is sent upstream.

## Base URL swap in client SDKs

### OpenAI Python SDK

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://platform.blindsight.io/api/runtime-security/proxy/openai/v1",
    api_key="sk-...your-openai-key...",           # forwarded upstream
    default_headers={
        "X-API-Key": "ak_...your-blindsight-api-key...",   # Blindsight auth
        "X-Blindsight-App-Id": "5d7f1c0e-8b6a-4e0b-9c52-3f1a2b7d9e44",
    },
)

client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
)
```

### OpenAI TypeScript SDK

```ts
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://platform.blindsight.io/api/runtime-security/proxy/openai/v1",
  apiKey: process.env.OPENAI_API_KEY,
  defaultHeaders: {
    "X-API-Key": process.env.BLINDSIGHT_API_KEY!,
    "X-Blindsight-App-Id": process.env.BLINDSIGHT_APP_ID!,
  },
});
```

### Anthropic Python SDK

```python
from anthropic import Anthropic

client = Anthropic(
    base_url="https://platform.blindsight.io/api/runtime-security/proxy/anthropic",
    api_key="sk-ant-...your-anthropic-key...",    # forwarded upstream as x-api-key
    default_headers={
        "X-Blindsight-Key": "ak_...your-blindsight-api-key...",  # Blindsight auth
        "X-Blindsight-App-Id": "5d7f1c0e-8b6a-4e0b-9c52-3f1a2b7d9e44",
    },
)

client.messages.create(
    model="claude-opus-4-6",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Hello"}],
)
```

OpenAI puts its upstream key in `Authorization` and Anthropic puts its in
`x-api-key`. To avoid a clash, OpenAI-style clients send the Blindsight key as
`X-API-Key` and Anthropic clients send it as `X-Blindsight-Key`.

### Plain HTTP

```bash
curl -X POST "https://platform.blindsight.io/api/runtime-security/proxy/openai/v1/chat/completions" \
  -H "X-API-Key: $BLINDSIGHT_API_KEY" \
  -H "X-Blindsight-App-Id: 5d7f1c0e-8b6a-4e0b-9c52-3f1a2b7d9e44" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "gpt-4o", "messages": [{"role": "user", "content": "Hello"}]}'
```

A clean request returns the provider's own response, unchanged. If the prompt
or the reply contains personal data, the proxy rewrites that text in place
before forwarding it. If the request is blocked, you get a provider-shaped
error (see [Errors](#errors)).

### OpenAI-compatible providers

The OpenAI SDK works against the `/openai-compatible/v1` route. Pick the
upstream with `X-Blindsight-Upstream-Provider`.

```python
client = OpenAI(
    base_url="https://platform.blindsight.io/api/runtime-security/proxy/openai-compatible/v1",
    api_key="gsk_...your-groq-key...",
    default_headers={
        "X-API-Key": "ak_...",
        "X-Blindsight-App-Id": "5d7f1c0e-8b6a-4e0b-9c52-3f1a2b7d9e44",
        "X-Blindsight-Upstream-Provider": "groq",   # groq|deepseek|perplexity|mistral|openrouter|cerebras
    },
)
```

An App whose routing names a provider or an upstream base URL uses it by
default, so the header is then optional for that App's traffic. A request that
names no upstream and has no App routing returns `400`.

### Self-hosted runtimes

Ollama, llama.cpp, vLLM and TGI use the same route with
`X-Blindsight-Upstream-Base`. The deployment must allow the base URL first.

```python
client = OpenAI(
    base_url="https://platform.blindsight.io/api/runtime-security/proxy/openai-compatible/v1",
    api_key="not-needed-for-ollama",
    default_headers={
        "X-API-Key": "ak_...",
        "X-Blindsight-Upstream-Base": "http://ollama.internal:11434/v1",
    },
)
```

### Google Gemini

```bash
curl -X POST "https://platform.blindsight.io/api/runtime-security/proxy/gemini/v1beta/models/gemini-1.5-pro:generateContent" \
  -H "X-API-Key: $BLINDSIGHT_API_KEY" \
  -H "x-goog-api-key: $GOOGLE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"contents": [{"role": "user", "parts": [{"text": "Hello"}]}]}'
```

The proxy forwards the `x-goog-api-key` header to Google.

### Google Vertex AI

Send an OAuth `Authorization: Bearer <access-token>` header, as you would to
Vertex directly. The path carries the project, location, publisher and model.
The proxy routes to `https://{location}-aiplatform.googleapis.com`.

```bash
curl -X POST "https://platform.blindsight.io/api/runtime-security/proxy/vertex/v1/projects/my-proj/locations/us-central1/publishers/google/models/gemini-1.5-pro:generateContent" \
  -H "X-API-Key: $BLINDSIGHT_API_KEY" \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  -d '{"contents": [{"role": "user", "parts": [{"text": "Hello"}]}]}'
```

### AWS Bedrock (Converse API)

Bedrock needs the request body signed with AWS SigV4. The proxy signs each
upstream call for you, so you pass your AWS credentials in headers.

```bash
curl -X POST "https://platform.blindsight.io/api/runtime-security/proxy/bedrock/model/anthropic.claude-3-5-sonnet-20241022-v2:0/converse" \
  -H "X-API-Key: $BLINDSIGHT_API_KEY" \
  -H "X-Blindsight-AWS-Access-Key-Id: $AWS_ACCESS_KEY_ID" \
  -H "X-Blindsight-AWS-Secret-Access-Key: $AWS_SECRET_ACCESS_KEY" \
  -H "X-Blindsight-AWS-Session-Token: $AWS_SESSION_TOKEN" \
  -H "X-Blindsight-AWS-Region: us-east-1" \
  -H "Content-Type: application/json" \
  -d '{"messages": [{"role": "user", "content": [{"text": "Hello"}]}]}'
```

`X-Blindsight-AWS-Session-Token` is only needed for temporary credentials. These
headers are used for the signature and are never forwarded.

## What is scanned

| Route                   | Prompt side                                                          | Reply side                                  |
| ----------------------- | -------------------------------------------------------------------- | ------------------------------------------- |
| OpenAI chat and compatible | `messages` with the role `user`, `system`, `developer`, `tool` or `function`, as a string or as text parts | `choices[].message`                |
| OpenAI legacy completions | `prompt`, as a string or a list                                    | `choices[].text`                            |
| Anthropic Messages      | `system` and `messages` with the role `user`                          | `content[]` text blocks                     |
| Gemini and Vertex       | `systemInstruction` and `contents` from the user                      | `candidates[].content.parts[].text`         |
| Bedrock Converse        | `system` and `messages` with the role `user`                          | `output.message.content[].text`             |

Assistant turns in the request are not scanned as prompts. When several fields are
scanned, the request gets the most severe verdict among them, and a `redact`
rewrites only the matching text.

## Streaming

Streaming is supported on:

- OpenAI chat completions (`stream: true`)
- Anthropic messages (`stream: true`)
- OpenAI-compatible chat completions
- Gemini and Vertex `:streamGenerateContent`

Upstream chunks reach your client straight away while the firewall scans the
reply as it builds up. On a `block` the stream ends with a terminal chunk in the
provider's own shape.

Streaming is not available on the legacy OpenAI and OpenAI-compatible
`/v1/completions` routes (`400` if you ask for it) or on Bedrock
`converse-stream`. Use the non-streaming Bedrock `/converse` route instead.

## Errors

Blocks and proxy failures use each provider's own error shape, so your SDK's
error handling keeps working.

OpenAI and OpenAI-compatible:

```json
{
  "error": {
    "message": "Blocked by Blindsight Runtime Security",
    "type": "blindsight_runtime_security",
    "param": null,
    "code": "blindsight_blocked"
  }
}
```

Anthropic:

```json
{
  "type": "error",
  "error": {"type": "invalid_request_error", "message": "Blocked by Blindsight Runtime Security"}
}
```

Gemini and Vertex:

```json
{"error": {"code": 400, "status": "blindsight_blocked", "message": "Blocked by Blindsight Runtime Security"}}
```

Bedrock:

```json
{"message": "Blocked by Blindsight Runtime Security", "type": "blindsight_blocked"}
```

The `message` can carry a short reason after the text shown.

| Status | When                                                              | Code                                   |
| ------ | ----------------------------------------------------------------- | -------------------------------------- |
| `400`  | The prompt was blocked                                            | `blindsight_blocked`                   |
| `400`  | Invalid JSON, or streaming requested on a route without it        |                                        |
| `402`  | The workspace allowance is used up                                |                                        |
| `413`  | The request body is larger than 16 MB                             |                                        |
| `502`  | The upstream could not be reached                                 | `upstream_error`                       |
| `502`  | The reply was blocked                                             | `upstream_blocked`                     |
| `503`  | The firewall is disabled for the workspace                        |                                        |

On Bedrock the `type` field carries the code. It also uses `missing_credentials`
(`401`), `missing_region` (`400`) and `sign_error` (`500`).

When the upstream provider itself answers with an error, the proxy returns the
provider's status and body untouched. Only blocks that Blindsight raised use
the shapes above.

## Events

Each proxy call writes an input event and, when the prompt was not blocked, an
output event. They appear in the [event log](/runtime-security/observability)
with `source_app` set to `proxy:<provider>` (for example `proxy:openai`) so you
can tell proxy traffic from direct scan calls. Analytics, drift and the event
list cover proxy traffic automatically.

## Limits

- Request bodies are limited to 16 MB.
- To check an agent's tool call before you run it, use
  [`/scan/tool-call`](/runtime-security/scan-api).

## Self-hosted deployments

If you run Blindsight yourself, these environment variables control the proxy.

| Variable                                     | Default                                      | Meaning                                                                     |
| -------------------------------------------- | -------------------------------------------- | --------------------------------------------------------------------------- |
| `RUNTIME_SECURITY_OPENAI_BASE_URL`           | `https://api.openai.com`                     | The OpenAI upstream origin.                                                 |
| `RUNTIME_SECURITY_ANTHROPIC_BASE_URL`        | `https://api.anthropic.com`                  | The Anthropic upstream origin.                                              |
| `RUNTIME_SECURITY_GEMINI_BASE_URL`           | `https://generativelanguage.googleapis.com`  | The Google AI Studio origin. Vertex takes its origin from the request path. |
| `RUNTIME_SECURITY_OPENAI_COMPAT_ALLOWLIST`   | empty (all six providers)                    | Comma-separated subset of `groq,deepseek,perplexity,mistral,openrouter,cerebras`. |
| `RUNTIME_SECURITY_OPENAI_COMPAT_EXTRA_BASES` | empty                                        | Comma-separated `http(s)://` bases callers may target with `X-Blindsight-Upstream-Base`. |
| `RUNTIME_SECURITY_PROXY_TIMEOUT`             | `60`                                         | Upstream request timeout in seconds.                                        |
| `RUNTIME_SECURITY_MAX_REQUEST_BODY_BYTES`    | `16777216`                                   | Largest request body the proxy accepts.                                     |

The proxy must sit behind TLS, because it carries both your provider key and
your prompts. The backend needs outbound access to each provider you enable.
