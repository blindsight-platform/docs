---
title: "Scan API"
description: "Explicit endpoints for scanning prompts, responses, batches and agent tool calls. Two HTTP calls around your model give you the full firewall."
---

The Scan API is the explicit integration mode. You make one call
before sending a prompt to the model and one call after the response
comes back. Useful when you don't want to put a proxy in the chat
hot path, or when you're scanning text that isn't going to an LLM at
all (batch pipelines, document ingestion, knowledge‑base curation).

All scan endpoints return **HTTP 200 with a JSON body even when the
verdict is `block`**. The verdict lives in the body so your code can
decide what to do. Non‑200 codes are reserved for protocol failures
(auth, rate limit, quota, an invalid request).

## Authentication

Send an [API key](/administration/api-keys) in the `X-API-Key` header. The
key needs the **Scan prompts and responses** permission (`runtime:scan`). A key
with **Full Runtime Access** (`runtime:*`) or full platform access also works.

To attribute traffic to an App, add `X-Blindsight-App-Id` with the App's UUID.
A key that is limited to one App uses that App without the header. A key that
is limited to several Apps must send it. If the workspace has exactly one App,
traffic is attributed to it when you omit the header.

| Status | When                                                                                   |
| ------ | -------------------------------------------------------------------------------------- |
| `401`  | The key is missing, invalid, expired or disabled.                                      |
| `402`  | The workspace has used its request allowance for the current period (`QUOTA_EXCEEDED`). |
| `403`  | The key does not have the `runtime:scan` permission, or its owner no longer holds it.  |
| `404`  | Runtime Security (or, for tool calls, the agentic guardrails module) is not enabled for the workspace. |
| `413`  | A text field is longer than the workspace limit (`PAYLOAD_TOO_LARGE`). The default limit is 32,000 characters. |
| `422`  | The request body is not valid.                                                         |
| `429`  | You are over the rate limit. Limits apply per API key.                                 |
| `503`  | The firewall is disabled or still starting.                                            |

## `POST /api/runtime-security/scan/input`

Scan a user prompt before forwarding it to your LLM.

### Request

| Field           | Type   | Required | Notes                                                                       |
| --------------- | ------ | -------- | --------------------------------------------------------------------------- |
| `text`          | string | yes      | The prompt to scan. Up to 32,000 characters by default.                      |
| `session_id`    | string | no       | Your identifier for the conversation or agent run (up to 200 characters). Send the same value on every call of one run so related calls are judged together. |
| `history`       | array  | no       | Up to 16 earlier turns of the conversation, oldest first. Each entry is a string or an object with `role` and `content`. |
| `untrusted`     | array  | no       | Up to 32 parts of the prompt that did not come from the user, such as retrieved documents. Each entry has `content`, and optionally `source` (`retrieval`, `tool_result`, `web`, `email`, `file`, `document`, `user_upload`, `other`) and `label`. |
| `source_app`    | string | no       | Free‑form app identifier (up to 128 chars). Diagnostic; not the App UUID.    |
| `provider`      | string | no       | `openai`, `anthropic`, `gemini`, `vertex`, `bedrock`, `groq`, and so on. Up to 32 chars. |
| `model`         | string | no       | Model name (up to 128 chars).                                                |
| `metadata`      | object | no       | Anything you want kept on the audit record.                                  |
| `custom_params` | object | no       | Typed key / value pairs declared by the resolved App.                        |

### Response

| Field           | Notes                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------- |
| `uuid`          | The event identifier. Empty when the workspace has event logging turned off.                 |
| `verdict`       | `allow`, `flag`, `redact` or `block`. See [Verdicts](/runtime-security/verdicts).            |
| `pii`           | `count` and `categories` of the personal data found.                                         |
| `redacted_text` | The text with personal data replaced by `<CATEGORY>` markers. Equal to the original when nothing was redacted. |
| `text_length`   | Length of the scanned text in characters.                                                    |
| `latency_ms`    | How long the scan took, in milliseconds.                                                     |

```bash
curl -X POST "https://platform.blindsight.io/api/runtime-security/scan/input" \
  -H "X-API-Key: $BLINDSIGHT_API_KEY" \
  -H "X-Blindsight-App-Id: 5d7f1c0e-8b6a-4e0b-9c52-3f1a2b7d9e44" \
  -H "Content-Type: application/json" \
  -d '{"text": "Please email the report to jane.doe@example.com", "session_id": "chat-8841"}'
```

```json
{
  "uuid": "9c2f6a41-0d3e-4b8a-a1c7-5e8d2f3b6a90",
  "verdict": "redact",
  "pii": {"count": 1, "categories": ["email"]},
  "redacted_text": "Please email the report to <EMAIL>",
  "text_length": 47,
  "latency_ms": 12
}
```

The response carries further fields that describe how the scan reached its
result. Only the fields above are part of the supported contract.

Rate limit: **200 requests per second per API key**.

## `POST /api/runtime-security/scan/output`

Scan an LLM response before returning it to the user.

### Request

| Field           | Type   | Required | Notes                                                  |
| --------------- | ------ | -------- | ------------------------------------------------------ |
| `response`      | string | yes      | The model output to scan. Up to 32,000 characters by default. |
| `prompt`        | string | no       | The prompt that produced it (for context).             |
| `session_id`    | string | no       | As above.                                              |
| `source_app`    | string | no       | As above.                                              |
| `provider`      | string | no       | As above.                                              |
| `model`         | string | no       | As above.                                              |
| `metadata`      | object | no       | As above.                                              |
| `custom_params` | object | no       | As above.                                              |

### Response

The same fields as `/scan/input`.

```bash
curl -X POST "https://platform.blindsight.io/api/runtime-security/scan/output" \
  -H "X-API-Key: $BLINDSIGHT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt": "Who is our contact?", "response": "Call Jane Doe on +41 79 555 01 02."}'
```

```json
{
  "uuid": "3a8e51d0-77c2-4f19-b6a4-2c9d1e0f8b35",
  "verdict": "redact",
  "pii": {"count": 1, "categories": ["phone"]},
  "redacted_text": "Call Jane Doe on <PHONE>.",
  "text_length": 33,
  "latency_ms": 9
}
```

Rate limit: **200 requests per second per API key**.

## `POST /api/runtime-security/scan/batch`

Scan up to 32 items in one call. Each item still uses one request from your
allowance, but you save the HTTP overhead.

### Request

| Field   | Type  | Required | Notes                     |
| ------- | ----- | -------- | ------------------------- |
| `items` | array | yes      | 1 to 32 items.            |

Each item:

| Field        | Type   | Required | Notes                                                    |
| ------------ | ------ | -------- | -------------------------------------------------------- |
| `text`       | string | yes      | The text to scan.                                        |
| `direction`  | string | no       | `input` (default) or `output`.                           |
| `source_app` | string | no       | As above.                                                |
| `provider`   | string | no       | As above.                                                |
| `model`      | string | no       | As above.                                                |
| `metadata`   | object | no       | As above.                                                |

```bash
curl -X POST "https://platform.blindsight.io/api/runtime-security/scan/batch" \
  -H "X-API-Key: $BLINDSIGHT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"items": [
        {"text": "first prompt", "direction": "input"},
        {"text": "model response here", "direction": "output"}
      ]}'
```

### Response

`results` holds one entry per item, in the same order, with the same fields as
`/scan/input`.

```json
{
  "results": [
    {"uuid": "b1d4…", "verdict": "allow", "pii": {"count": 0, "categories": []}, "redacted_text": "first prompt", "text_length": 12, "latency_ms": 8},
    {"uuid": "c7e2…", "verdict": "allow", "pii": {"count": 0, "categories": []}, "redacted_text": "model response here", "text_length": 19, "latency_ms": 8}
  ]
}
```

Rate limit: **40 requests per second per API key**. Each batch uses
`len(items)` requests from your allowance. If the workspace runs out partway
through, the call returns `402`.

A batch cannot be attributed to an App. A key that is limited to specific Apps
gets `400` with the code `APP_SCOPED_KEY`; use `/scan/input` and `/scan/output`
with `X-Blindsight-App-Id` for those keys.

## `POST /api/runtime-security/scan/tool-call`

Check an agent's tool call before you run it. This endpoint is part of the
agentic guardrails module; a workspace without it gets `404`.

### Request

| Field        | Type   | Required | Notes                                                                      |
| ------------ | ------ | -------- | -------------------------------------------------------------------------- |
| `tool_name`  | string | yes      | The tool being called (up to 200 characters).                              |
| `arguments`  | any    | no       | The arguments: an object, array, string or number. Defaults to `{}`.       |
| `session_id` | string | no       | As above.                                                                  |
| `source_app` | string | no       | As above.                                                                  |
| `provider`   | string | no       | As above.                                                                  |
| `model`      | string | no       | As above.                                                                  |
| `metadata`   | object | no       | As above.                                                                  |

### Response

| Field                | Notes                                                                                  |
| -------------------- | -------------------------------------------------------------------------------------- |
| `uuid`               | The event identifier. Empty when event logging is off.                                 |
| `verdict`            | `allow`, `redact` or `block`.                                                          |
| `reasons`            | The rules that applied: a list of `code`, `severity` and `detail`. For example `tool.denied` when the tool is on the deny list, `tool.not_allowed` when an allow list exists and the tool is not on it, and `tool.args_too_large` when the arguments exceed the size limit. |
| `redacted_arguments` | The arguments with personal data masked. Use these when `verdict` is `redact`.         |
| `pii`                | `count` and `categories` of the personal data found in the arguments.                  |
| `arg_bytes`          | Size of the JSON‑serialised arguments in bytes.                                        |
| `latency_ms`         | How long the check took, in milliseconds.                                              |

```bash
curl -X POST "https://platform.blindsight.io/api/runtime-security/scan/tool-call" \
  -H "X-API-Key: $BLINDSIGHT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"tool_name": "send_email", "arguments": {"to": "jane.doe@example.com", "body": "Hello"}}'
```

```json
{
  "uuid": "e4a9c2b7-1f60-4d83-8a35-6b7c0d2e9f18",
  "verdict": "redact",
  "reasons": [],
  "redacted_arguments": {"to": "<EMAIL>", "body": "Hello"},
  "pii": {"count": 1, "categories": ["email"]},
  "arg_bytes": 52,
  "latency_ms": 3
}
```

Rate limit: **200 requests per second per API key**.

## Wrapping it around your model

The minimal integration: scan input, call your model, scan output.

```python
import httpx

BLINDSIGHT = httpx.Client(
    base_url="https://platform.blindsight.io",
    headers={
        "X-API-Key": "ak_live_…",
        "X-Blindsight-App-Id": "app_…",
    },
    timeout=10.0,
)

def safe_chat(user_text: str) -> str:
    # Pre-flight
    pre = BLINDSIGHT.post(
        "/api/runtime-security/scan/input",
        json={"text": user_text},
    )
    pre.raise_for_status()
    v = pre.json()
    if v["verdict"] == "block":
        raise PermissionError(f"Blocked (event: {v['uuid']})")
    # "flag" and "allow" both fall through here: flag is a recording
    # verdict, redacted_text is unchanged from the original for it.
    safe_text = v["redacted_text"] if v["verdict"] == "redact" else user_text

    # Your model
    response = call_my_llm(safe_text)

    # Post-flight
    post = BLINDSIGHT.post(
        "/api/runtime-security/scan/output",
        json={"prompt": safe_text, "response": response},
    )
    post.raise_for_status()
    o = post.json()
    if o["verdict"] == "block":
        return f"I can't share that. (event: {o['uuid']})"
    return o["redacted_text"] if o["verdict"] == "redact" else response
```

See [SDK examples](/runtime-security/sdk-examples) for Node, curl,
LangChain, and LlamaIndex variants.

## When to prefer the Scan API over the proxy

- You don't want the firewall in the chat request path.
- You're scanning text that isn't going to an LLM at all.
- You're processing a large batch (`/scan/batch` is the right tool).
- You're wiring custom middleware in a language without a maintained
  OpenAI / Anthropic SDK.

For chat traffic that does go to a standard SDK, the
[reverse proxy](/runtime-security/reverse-proxy) is faster to set up
and harder to bypass.
